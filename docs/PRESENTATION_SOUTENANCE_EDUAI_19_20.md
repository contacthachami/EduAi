## Slide 10 - Pipeline IA : le coeur technique d'EduAI

Message principal : La valeur technique d'EduAI vient de l'orchestration d'un pipeline IA complet.

Contenu exact à mettre sur la slide :

```text
PDF
↓
Extraction texte - PyMuPDF
↓
Chunking intelligent - 400 tokens + overlap 50
↓
Embeddings multilingues - MiniLM 384 dimensions
↓
Indexation vectorielle - FAISS IndexFlatIP
↓
Recherche top-3 chunks
↓
RAG avec Llama 3.3 70B via Groq
↓
Réponse - Résumé - Quiz - Flashcards - Mindmap - Examen
```

Suggestions visuelles :
- Schéma horizontal en pipeline avec 7 blocs.
- Utiliser une couleur différente pour chaque famille :
  - Document : gris
  - NLP : bleu clair
  - Vectoriel : bleu EduAI
  - LLM : accent chaud
  - Sorties : bleu sombre
- Ajouter sous FAISS : "similarité sémantique".

Notes orales :

> Le coeur technique d'EduAI est ce pipeline. Lors de l'upload, le PDF est lu avec PyMuPDF, puis découpé en chunks de 400 tokens avec un overlap de 50 pour préserver le contexte. Chaque chunk est transformé en vecteur de 384 dimensions grâce au modèle multilingue MiniLM. Ces vecteurs sont indexés dans FAISS avec IndexFlatIP. Lorsqu'une question est posée, EduAI recherche les trois passages les plus pertinents, les injecte dans le prompt, puis Llama 3.3 70B génère une réponse contextualisée. Le même socle permet ensuite de produire résumés, quiz, flashcards, mindmap et examens.

# Questions probables du jury et réponses professionnelles

## 1. Pourquoi utiliser RAG au lieu d'envoyer directement le PDF au LLM ?

Réponse :

Le RAG permet d'ancrer les réponses dans le contenu réel du cours. Au lieu de demander au LLM de répondre de manière générale, EduAI recherche d'abord les passages les plus pertinents dans le PDF, puis les injecte dans le contexte de génération. Cela améliore la précision, réduit le risque d'hallucination et permet d'afficher des sources vérifiables à l'étudiant.

---

## 2. Pourquoi avoir choisi FAISS ?

Réponse :

FAISS est une bibliothèque spécialisée dans la recherche vectorielle rapide. Elle est adaptée aux systèmes RAG parce qu'elle permet de comparer efficacement la question de l'étudiant avec les vecteurs des passages du cours. Dans EduAI, FAISS IndexFlatIP est utilisé avec des vecteurs normalisés, ce qui permet une recherche par similarité sémantique. C'est simple, rapide et suffisant pour un volume de cours étudiant.

---

## 3. Pourquoi MiniLM multilingue ?

Réponse :

Le modèle `paraphrase-multilingual-MiniLM-L12-v2` offre un bon compromis entre qualité, vitesse et légèreté. Il produit des embeddings de 384 dimensions, ce qui est plus léger que des modèles plus grands, tout en restant performant pour la recherche sémantique. Son aspect multilingue est important pour le contexte marocain, où les cours peuvent contenir du français, de l'arabe ou de l'anglais technique.

---

## 4. Comment gérez-vous le risque d'hallucination ?

Réponse :

EduAI réduit ce risque à plusieurs niveaux. D'abord, les réponses sont générées à partir des chunks récupérés dans le cours, pas seulement à partir de la mémoire générale du modèle. Ensuite, les sources sont affichées pour permettre la vérification. Enfin, il existe un fallback extractif avec CamemBERT si le LLM n'est pas disponible. Malgré cela, je reste prudent : le système assiste l'étudiant, mais ne remplace pas la validation pédagogique par l'enseignant.

---

## 5. Pourquoi FastAPI pour le backend ?

Réponse :

FastAPI est adapté à ce projet pour trois raisons. Premièrement, il est basé sur Python, ce qui facilite l'intégration des bibliothèques IA/NLP comme PyMuPDF, sentence-transformers, FAISS ou spaCy. Deuxièmement, il est performant et supporte bien les traitements asynchrones. Troisièmement, il s'intègre avec Pydantic, ce qui permet de valider proprement les données d'entrée et de sortie.

---

## 6. EduAI peut-il passer à l'échelle ?

Réponse :

La version actuelle est pensée comme une base déployable et évolutive. Docker Compose et Portainer facilitent le déploiement. MongoDB peut être externalisé ou répliqué. FAISS peut être conservé pour une première phase, puis remplacé ou complété par une base vectorielle distribuée si le volume augmente. Le traitement LLM peut aussi être optimisé par cache, quotas par plan et génération en arrière-plan.

## 7. Quelle est la différence entre EduAI et ChatGPT ?

Réponse :

ChatGPT est un assistant généraliste. EduAI est une plateforme spécialisée dans l'apprentissage à partir de PDF de cours. La différence principale est l'intégration du cycle pédagogique complet : upload du cours, RAG contextualisé, sources, résumé, quiz, flashcards, mindmap, examen, suivi et administration. EduAI est donc centré sur le cours réel de l'étudiant et sur la révision, pas seulement sur la conversation.

---

## 8. Quelles sont les limites actuelles du projet ?

Réponse :

Les limites principales sont liées à la qualité des PDF, au coût potentiel des appels LLM à grande échelle et à la nécessité de tester avec davantage d'étudiants réels. Certains documents scannés ou mal structurés peuvent nécessiter une couche OCR future. Le modèle économique doit aussi être validé sur le terrain. C'est pour cela que je présente EduAI comme une base fonctionnelle et déployable, avec un potentiel commercial, mais qui doit encore passer par une phase pilote.
